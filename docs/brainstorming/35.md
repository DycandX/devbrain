# 23. Prinsip desain yang saya pegang

Kalau kita lanjut membangun ini, saya akan menjaga 8 prinsip:

**1. One memory, many agents**

```text
             Memory
          ↙ ↓ ↓ ↓ ↘
       agents/tools
```

**2. User owns the data**

Semua memory bisa dilihat, diedit, export, dan delete.

**3. Human-readable**

Markdown/Obsidian tetap menjadi interface penting.

**4. Machine-readable**

YAML/JSON/database untuk machine layer.

**5. Explicit > inferred**

Apa yang user katakan langsung lebih kuat daripada AI menebak.

**6. Scoped memory**

Global ≠ project ≠ task ≠ session.

**7. Traceable**

Setiap memory tahu sumbernya.

**8. Agent-agnostic**

Jangan membuat sistem yang hanya bekerja dengan Claude/Codex.

## Dan satu hal yang menurut saya sangat penting

Jangan menyebutnya sekadar **"AI Memory"**.

Karena requirement-mu sebenarnya lebih besar:

```text
                ┌─────────────────────┐
                │      AI MEMORY      │
                └─────────────────────┘
                          +
                ┌─────────────────────┐
                │    KNOWLEDGE BASE    │
                └─────────────────────┘
                          +
                ┌─────────────────────┐
                │   PROJECT CONTEXT    │
                └─────────────────────┘
                          +
                ┌─────────────────────┐
                │   CURRENT STATE      │
                └─────────────────────┘
                          +
                ┌─────────────────────┐
                │    USER INTENT       │
                └─────────────────────┘
                          ↓
                 CENTRAL CONTEXT
```

Jadi target akhirnya lebih tepat:

> **A local-first, agent-agnostic Personal AI Context Layer that provides persistent memory, knowledge, project context, and user preferences to every AI agent and AI tool.**

Dan **Obsidian menjadi human-facing knowledge layer**, bukan keseluruhan sistem.

Kalau kita mau serius membangunnya, langkah berikutnya menurut saya bukan langsung coding. Kita perlu **merancang specification-nya dulu**: `Memory Model → Knowledge Model → Context Model → Storage → Retrieval → MCP/API → Agent adapters → Sync/Git → security/privacy`. Dari situ baru kita bisa menentukan apakah backend-nya cukup **SQLite + filesystem**, perlu **Postgres**, perlu vector DB, dan bagaimana membuatnya benar-benar kompatibel dengan Codex/Claude Code/Antigravity/OpenCode/CLI.
