## Ringkasan

Semua agent kini bisa menyimpan dan memperbaiki skill di vault, dan skill itu langsung terbaca oleh agent lain, termasuk Hermes lewat folder skill bersama dari Sprint 16. Polanya meniru `skill_manage` Hermes ([dokumen 49](../brainstorming/49-siklus-belajar-hermes-dan-adopsinya-di-devbrain.md)), ditambah gerbang tulis yang sama dengan memori.

---

## 🚀 Ditambahkan

### 1. Tool MCP `save_skill` dan `patch_skill` (`skills/manager.py`)
- `save_skill(name, description, body)` membuat skill, atau mengganti skill yang dibuat agent.
- `patch_skill(name, old_text, new_text)` mengganti satu potongan teks yang muncul tepat sekali.
- Format mengikuti agentskills.io: frontmatter `name` dan `description`, isi Markdown, dan folder `references/` opsional.
- Validasi: nama huruf kecil, angka, dan tanda hubung (maksimal 64 karakter); deskripsi 1 sampai 1.024 karakter; `SKILL.md` maksimal 24.000 karakter.
- Deskripsi tool mengarahkan agent menyimpan alur kerja yang tidak sepele, yang ditemukan setelah memperbaiki error, atau yang dikoreksi pengguna. Tugas sekali jalan tidak perlu jadi skill.

### 2. Kepemilikan dan kunci
- Agent hanya boleh mengubah skill yang **dibuat agent**. Skill yang ditulis manual atau berasal dari luar hanya bisa dibaca agent.
- `devbrain skill lock <nama>` menutup skill dari perubahan agent sama sekali.

### 3. Gerbang tulis untuk skill
- Pemeriksa isi yang sama dengan memori menolak instruksi yang mengambil alih agent, kunci atau pengiriman data, kredensial, dan karakter tersembunyi.
- **Unduh-lalu-jalankan** (`curl ... | bash`) bisa jadi langkah instalasi yang sah. Tanpa mode persetujuan, skill seperti itu ditolak. Dengan mode persetujuan, skill itu ditahan dan diberi peringatan untuk peninjau.
- Mode persetujuan (`skills.write_approval`): skill baru dan perubahan menunggu di `.brain_data/pending_skills/`, di luar folder yang dibaca Hermes. Perubahan pada skill aktif menunggu di samping versi aktifnya, dan versi aktif tetap dipakai sampai disetujui.

### 4. `load_skill` bertahap
- Tanpa nama: daftar skill beserta deskripsi dan berkas referensinya.
- Dengan nama: isi `SKILL.md`.
- Dengan `path`: satu berkas referensi. Path di luar folder skill ditolak.

### 5. Registry dan ledger skill
- Tabel `skills` mencatat pembuat, status, kunci, jumlah dimuat, dan jumlah diperbaiki. Datanya disiapkan untuk curator di Sprint 18.
- Tabel `skill_ledger` mencatat setiap tindakan: dibuat, diperbarui, diperbaiki, ditahan, disetujui, ditolak, diblokir, dikunci.

### 6. Perintah `devbrain skill`
`pending [--show]`, `approve <nama...|all>`, `reject <nama...|all>`, `lock`, `unlock`, `ledger`.

## ⚖️ Keputusan dan Penyimpangan

- **`skills.write_approval` diaktifkan di vault utama**, mengikuti alasan D15-1: skill dari satu agent dibaca semua agent.
- **S17-T07 tidak dikerjakan:** `skills.create_dir` Hermes tidak diarahkan ke vault. Kalau diarahkan, Hermes akan menulis skill langsung ke folder bersama tanpa melewati pemeriksa isi dan persetujuan DevBrain. Hermes tetap membaca skill vault (D16-2), dan bisa menyimpan skill bersama lewat tool `save_skill`.
- **Nama ketat hanya untuk skill baru.** Skill lama dengan garis bawah (misalnya `example_skill`) tetap bisa dimuat.

## ⏭️ Keterbatasan

- Agent belum bisa menambah berkas `references/` lewat MCP. Berkas tambahan ditulis manual atau lewat `patch_skill` di `SKILL.md`.
- Pemeriksa isi berbasis pola. Persetujuan pemilik tetap pertahanan utama.
