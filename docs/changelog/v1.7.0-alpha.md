## Ringkasan

Rilis ini tidak menambah fitur besar. Isinya memperbaiki hal yang rusak, membuat kualitas pencarian bisa diukur, lalu memperbaikinya berdasarkan ukuran itu.

## ⚠️ Yang Perlu Dilakukan Setelah Update

1. **Indeks ulang vault.** Vault baru memakai model embedding multibahasa. Vault lama tetap memakai model yang tertulis di `.brainrc.json` miliknya. Untuk pindah, ubah `embedding_model` di `.brainrc.json` menjadi `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, lalu jalankan `devbrain index`. Indeks lama dibuang otomatis karena modelnya berbeda. Unduhan pertama sekitar 220 MB.
2. **Daftarkan ulang MCP server.** Entri `central-brain` di config IDE bisa saja masih menunjuk ke folder sementara pytest akibat bug yang diperbaiki di rilis ini. Jalankan `devbrain init <path-vault-utama>` untuk memperbaikinya.
3. **Pasang ulang dependensi** (`pip install -e .`), karena `mcp` kini dipin ke versi 2.

## 🐛 Diperbaiki

### 1. Test suite menimpa config IDE asli
- **Masalah:** `test_cli_init_and_status` menjalankan `devbrain init` tanpa mengganti home directory. Setiap `pytest` menulis ulang `~/.claude.json` dan tiga `mcp_config.json` Antigravity sehingga `central-brain` menunjuk ke vault sementara yang kemudian dihapus.
- **Perbaikan:** fixture `autouse` `isolated_home` di `tests/conftest.py` mengarahkan `Path.home()`, `HOME`, `USERPROFILE`, dan `APPDATA` ke folder sementara untuk semua test.
- **Bukti:** checksum `~/.claude.json` sama sebelum dan sesudah seluruh test dijalankan.

### 2. Config IDE bisa rusak atau tertimpa
- **Masalah:** file config ditulis langsung (tidak atomik). File yang gagal dibaca dianggap kosong lalu ditimpa, sehingga seluruh isinya hilang. `init` juga membuat folder di tiga lokasi Antigravity walau belum ada.
- **Perbaikan** (`core/client_config.py`, `core/fsutil.py`):
  - Penulisan lewat file sementara lalu `os.replace`.
  - Config yang tidak bisa diurai dibiarkan apa adanya, dan `init` memberi tahu pengguna.
  - Hanya lokasi Antigravity yang foldernya sudah ada yang disentuh. Bila tidak ada satu pun, hanya lokasi utama yang dibuat.

### 3. Dependensi tidak cocok dengan kode
- `mcp>=1.0.0` menjadi `mcp>=2.0.0`. Kode memakai `mcp.server.mcpserver.MCPServer` yang hanya ada di 2.x.
- `numpy` ditambahkan (dipakai langsung, sebelumnya hanya ikut terbawa).
- `pydantic-settings` dihapus (tidak dipakai). `typer[all]` menjadi `typer`.
- Versi di `pyproject.toml` disamakan dengan `__version__`.

### 4. Frontmatter log agent rusak oleh tanda kutip
- **Masalah:** `write_agent_log` menaruh `summary` mentah di dalam `title: "..."`. Tanda kutip di judul menghasilkan YAML yang tidak sah.
- **Perbaikan:** nilai frontmatter dibuat dengan `json.dumps`.

### 5. Template rules menulis signature tool yang salah
- `AGENTS.md` / `CLAUDE.md` hasil generator menyebut `write_agent_log(project, title, summary)`. Yang benar `write_agent_log(summary, details, tags)`.

### 6. Engine dibuat tanpa config vault
- **Masalah:** harvester membuat `HybridEngine(vault_path=...)` tanpa config, sehingga memakai model default dan mengabaikan pola ignore serta vault tertaut. Bila model default berbeda dengan model vault, vektor dari dua model bisa tercampur dalam satu indeks.
- **Perbaikan:** `HybridEngine.from_config()` dipakai di semua tempat.

## 🚀 Ditambahkan

### 1. Evaluasi kualitas pencarian (`benchmarks/eval_retrieval.py`)
- Korpus tetap berisi 16 catatan (Indonesia dan Inggris) dan 38 pertanyaan, termasuk pertanyaan lintas bahasa dan 6 pertanyaan yang memang tidak ada jawabannya.
- Metrik: `hit@1`, `hit@3`, `MRR`, dan `abstain` (bagian pertanyaan tanpa jawaban yang benar-benar mengembalikan nol hasil).
- Jalankan: `python benchmarks/eval_retrieval.py [--model <nama>]`.

### 2. Reciprocal Rank Fusion dan gerbang relevansi (`engine/hybrid_search.py`)
- **Sebelumnya:** `0.6 × dense + 0.4 × bm25`. Dense dipetakan ke 0,5 sampai 1,0 dan BM25 ke 0 sampai 1, sehingga BM25 menentukan urutan dan hasil selalu dikembalikan walau pertanyaannya tidak relevan.
- **Sekarang:**
  - Mode hybrid menggabungkan peringkat, bukan skor (RRF, k = 60).
  - Sebuah chunk menjadi kandidat semantik hanya bila cosine mentahnya mencapai batas bawah model (`EMBEDDING_MODEL_MIN_SIMILARITY`).
  - Sebuah chunk menjadi kandidat kata kunci hanya bila memuat minimal 50% kata dalam pertanyaan.
  - Chunk yang tidak lolos keduanya tidak dikembalikan.
- Skor yang ditampilkan: 1,0 berarti peringkat pertama di kedua pemeringkat.

### 3. Model embedding multibahasa sebagai default
- Default berubah dari `BAAI/bge-small-en-v1.5` (khusus Inggris) ke `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (sekitar 50 bahasa, 384 dimensi).
- Indeks kini mencatat model pembuatnya. Bila model berubah, indeks lama dibuang dan dibangun ulang.

### 4. Watcher tersambung ke `devbrain serve`
- `serve` menyalakan `VaultWatcher`, sehingga catatan yang diedit di Obsidian terindeks tanpa menunggu tool yang menulis. Bisa dimatikan dengan `--no-watch`.
- `HybridEngine` diberi kunci (`RLock`) karena kini dipakai bersama oleh server MCP dan thread watcher.
- Watcher memakai aturan ignore yang sama dengan engine (sebelumnya salinan terpisah).

### 5. Harvester Claude Code yang berguna (`harvester/claude_code.py`)
- **Sebelumnya:** satu catatan per folder projek, berisi 2.000 karakter JSON mentah, dan hanya sekali. Sesi berikutnya di projek yang sama tidak pernah masuk.
- **Sekarang:**
  - Satu catatan per sesi (satu file `.jsonl`).
  - Isi: tujuan, permintaan lanjutan, jawaban akhir, file yang diubah, dan statistik (jumlah giliran, panggilan tool, token masuk, keluar, cache baca, cache tulis).
  - Sesi yang bertambah panjang di-ingest ulang ke catatan yang sama.
  - Pesan sub-agent, pesan meta, dan keluaran harness dilewati. Pemakaian token dihitung sekali per pesan.
- Contoh nyata: transkrip 3,2 MB menjadi catatan 3,7 ribu karakter.

## 📊 Hasil Pengukuran

Diukur dengan `benchmarks/eval_retrieval.py`, mode hybrid, 32 pertanyaan berjawaban dan 6 tanpa jawaban.

| Konfigurasi | hit@1 ID | hit@1 EN | hit@1 semua | abstain |
| :--- | :---: | :---: | :---: | :---: |
| v1.6.0: model Inggris + jumlah berbobot | 1,000 | 0,786 | 0,906 | 0,000 |
| Model Inggris + RRF | 0,611 | 0,929 | 0,750 | 0,000 |
| **v1.7.0: model multibahasa + RRF** | **0,944** | **1,000** | **0,969** | **1,000** |

Catatan pembacaan:
- Pada v1.6.0, hasil hybrid **identik** dengan BM25 saja. Komponen semantik tidak ikut menentukan urutan.
- Model Inggris dengan RRF lebih buruk untuk pertanyaan Indonesia, karena sisi semantiknya lemah dan kini benar-benar ikut dihitung. Karena itu RRF dan model multibahasa dirilis bersama.
- Pemisahan cosine: dengan model Inggris, pertanyaan tanpa jawaban mencapai 0,775 sedangkan jawaban yang benar bisa serendah 0,578, jadi tidak ada batas yang memisahkan. Dengan model multibahasa: maksimum 0,375 untuk yang salah dan minimum 0,367 untuk yang benar, dengan median 0,576. Batas 0,38 dipilih dari data ini.

**Keterbatasan:** korpusnya kecil dan ditulis untuk tujuan ini, sehingga kata-katanya cenderung mirip dengan pertanyaannya. Angka di atas menunjukkan arah, bukan kinerja pada vault nyata. Batas 0,38 dikalibrasi dari 38 pertanyaan dan perlu diuji ulang dengan pertanyaan dari pemakaian sehari-hari.
