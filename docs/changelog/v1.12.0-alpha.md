## Ringkasan

DevBrain kini terpakai tanpa agent harus ingat memanggilnya, dan Hermes Agent memakai memori yang sama dengan Claude Code.

Keputusan yang dipakai:
- **D15-1:** `memory.write_approval` diaktifkan di vault utama. Memori dari agent mana pun menunggu persetujuan.
- **D16-1:** hook dipasang per projek.
- **D16-2:** skill vault hanya dibaca oleh Hermes. Skill buatan Hermes tetap ditulis di folder Hermes sendiri.

---

## 🚀 Ditambahkan

### 1. Hook Claude Code (`integrations/claude_hooks.py`, `devbrain hooks`)

| Hook | Yang dilakukan |
| :--- | :--- |
| `SessionStart` | Mencocokkan folder kerja dengan `local_path` kartu projek (yang terdalam menang), lalu memberi briefing: ringkasan projek, memori inti, memori projek, ADR aktif, sesi terakhir, dan pengingat untuk `remember` sebelum selesai |
| `SessionEnd` | Menjalankan panen sesi Claude Code di latar belakang, supaya menutup sesi tidak tertunda |

- Dipasang dengan `devbrain hooks install [folder]` ke `<projek>/.claude/settings.local.json`. Berkas itu khusus mesin ini dan tidak ikut di-commit.
- Hook lain di berkas itu tidak disentuh. Memasang ulang tidak menggandakan.
- `devbrain hooks uninstall` dan `devbrain hooks status`.
- Briefing di awal sesi tidak memakai model embedding, jadi cepat: **2,2 detik**, 3.176 karakter untuk projek devbrain.
- Hook tidak pernah gagal dengan keras. Kesalahan ditulis ke stderr dan sesi tetap berjalan.

### 2. Integrasi Hermes (`integrations/hermes.py`, `devbrain hermes`)
- **Lokasi Hermes:** `HERMES_HOME`, lalu `%LOCALAPPDATA%\hermes`, lalu `~/.hermes`.
- **`devbrain hermes connect`** menambahkan dua hal ke `config.yaml` Hermes:
  - DevBrain sebagai MCP server `central-brain`, dengan environment yang dibutuhkan Python dan FastEmbed (Hermes menyaring environment server stdio);
  - folder `00_System/Agent_Skills` vault ke `skills.external_dirs`.
- Config diedit per blok sebagai teks, sehingga komentar dan format pemilik tetap utuh. Cadangan bertanggal dibuat dulu, dan hasil edit harus terbaca YAML persis seperti yang dimaksud. Bila tidak, tidak ada yang ditulis.
- `devbrain hermes disconnect` dan `devbrain hermes status`.

### 3. Harvester Hermes (`harvester/hermes.py`)
- Sesi dibaca dari `state.db` dalam mode hanya-baca, sehingga gateway Hermes yang sedang berjalan tidak terganggu.
- Satu catatan per sesi di `90_Agent_Inbox/hermes/`: judul dari Hermes, kanal (misalnya `telegram: Homelab Command Center`), tujuan, permintaan lanjutan, hasil, tool yang dipakai, dan pemakaian token.
- Memori inti Hermes (`MEMORY.md`, `USER.md`) disalin ke `00_System/Hermes_Memory.md`. Berkas ini hanya ditulis ulang bila isinya berubah.
- `devbrain ingest --from hermes`.

## ⚖️ Penyimpangan dari Rencana

- **S16-T02, hook akhir sesi:** rencananya hook `Stop` meminta agent meringkas dan memanggil `remember`. Yang dibuat: briefing awal sesi sudah memuat pengingat itu, dan `SessionEnd` memanen sesi secara deterministik. Memaksa agent melanjutkan lewat hook `Stop` berisiko memicu putaran berulang dan menambah biaya token di setiap akhir giliran.
- **Uji langsung lewat Hermes belum dilakukan.** Menjalankan `hermes mcp add` pada salinan config memicu Hermes menyelesaikan pembaruannya yang tertunda (mengunduh dependensi), dan berhenti dengan saran `hermes update`. CLI Hermes tidak dijalankan lagi. Server diuji dengan perintah dan environment yang persis sama dengan yang ditulis di config Hermes.

---

## ⚠️ Yang Perlu Dilakukan Pemilik

1. Jalankan `hermes update` untuk menyelesaikan pembaruan Hermes yang tertunda.
2. Jalankan `hermes mcp test central-brain`, lalu mulai ulang gateway Hermes.
3. Mulai ulang Claude Code di repo ini untuk mencoba hook `SessionStart`.
4. Pasang hook di projek lain yang aktif: `devbrain hooks install <folder>`.
5. Tinjau memori dari agent secara berkala: `devbrain memory pending`.

---

## ⏭️ Keterbatasan

- Panen saat `SessionEnd` memindai semua projek Claude Code. Sesi yang tidak berubah dilewati dengan cepat, tetapi tetap dipindai.
- Indeks bisa ditulis oleh dua proses (server MCP dan panen latar belakang) pada saat yang sama. Penulisan atomik mencegah berkas rusak, tetapi satu proses bisa menimpa hasil proses lain. Panen atau perubahan berikutnya memperbaikinya.
- Curator Hermes tidak menyentuh skill dari `external_dirs`, jadi perawatan skill bersama menjadi tugas Sprint 18.
- Isi percakapan Telegram ikut tersimpan di vault. Sanitizer hanya menyamarkan kredensial.
