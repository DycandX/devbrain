## Ringkasan

Tiga hal baru, semuanya untuk tujuan yang sama: agent bisa mengingat antar sesi, dan biaya token dari memakai DevBrain menjadi kecil dan terukur.

1. Tool memori `remember`, `recall`, `forget`.
2. Keluaran tool yang dibatasi, dengan pola "ringkas dulu, detail saat diminta".
3. Perintah `devbrain usage` untuk melihat pemakaian token Claude Code per projek.

---

## 🚀 Ditambahkan

### 1. Memori jangka panjang (`memory/manager.py`)

| Tool MCP | Fungsi |
| :--- | :--- |
| `remember(content, scope, project, tags, supersedes)` | Menyimpan satu fakta, preferensi, atau pelajaran |
| `recall(query, project, limit)` | Mencari memori yang relevan |
| `forget(memory_id)` | Mempensiunkan memori yang salah atau usang |

Cara kerjanya:
- **SQLite adalah catatan resminya.** Tabel `memories` yang sudah ada sejak v1.6.0 kini benar-benar dipakai.
- **Setiap memori aktif punya cermin Markdown** di `00_System/Memories/<id>.md`, sehingga terlihat di Obsidian dan ikut terindeks untuk pencarian semantik.
- **Memori yang digantikan atau dilupakan tidak dihapus dari SQLite.** Statusnya berubah (`superseded` atau `forgotten`) dan cermin Markdown-nya dibuang, sehingga `recall` hanya melihat yang aktif.
- **Scope projek dijaga.** Memori `PROJECT` hanya muncul untuk projeknya. Memori `GLOBAL` muncul di semua projek.
- **Satu fakta per memori**, maksimal 1.000 karakter. Teks yang sama tidak disimpan dua kali.
- `build_task_context` kini memuat bagian **Remembered Facts** bila ada memori yang relevan.

### 2. Keluaran tool yang dibatasi

| Tool | Sebelumnya | Sekarang |
| :--- | :--- | :--- |
| `search_brain` | Cuplikan 300 karakter per chunk, satu catatan bisa mengisi semua slot | Satu baris per catatan (`detail="index"`). Cuplikan panjang lewat `detail="snippet"` |
| `read_note` (baru) | Tidak ada | Membaca satu catatan atau satu bagian (`heading`), dibatasi `max_chars` |
| `get_project_context` | Seluruh file, tanpa batas | Dibatasi 6.000 karakter, dengan petunjuk cara mengambil sisanya |
| `get_user_context` / briefing | `User_Preferences.md` dimuat utuh | Dibatasi 3.000 karakter |

- Hasil yang terpotong selalu menyebut berapa karakter yang tidak ditampilkan dan tool apa yang dipanggil untuk mengambilnya.
- `search_brain` dan briefing kini menampilkan satu hasil per catatan (`one_per_note`).
- Hasil pencarian memakai `doc_id` sebagai penunjuk, sehingga catatan dari vault tertaut (`linked:<alias>:<path>`) juga bisa dibaca dengan `read_note`.

### 3. Rekap pemakaian token (`devbrain usage`)

- Membaca field `usage` di transkrip Claude Code (`~/.claude/projects/`), hanya baca.
- Per projek: jumlah sesi, prompt, panggilan tool, panggilan ke tool `central-brain`, token konteks, rasio cache, dan token keluaran.
- Opsi: `--days N` (default 30, `0` untuk semua), `--top N`, `--json`.

## 🐛 Diperbaiki

### 1. Koneksi SQLite tidak pernah ditutup
- **Masalah:** `with sqlite3.connect(...) as conn` hanya mengakhiri transaksi, tidak menutup koneksi. Setiap operasi meninggalkan satu handle terbuka. Di Windows ini mengunci `brain.db` sehingga folder vault tidak bisa dihapus atau dipindah selama proses hidup.
- **Perbaikan:** `_get_connection()` kini context manager yang menutup koneksi.
- **Ditemukan saat:** skrip pengukuran gagal menghapus folder sementara.

### 2. `load_skill` dan pembacaan catatan bisa keluar dari vault
- **Masalah:** nama skill dipakai langsung sebagai bagian path, sehingga `../../x` bisa menunjuk ke `SKILL.md` di luar folder skill.
- **Perbaikan:** nama skill harus berupa nama folder biasa. `read_note` menolak path yang hasil resolusinya di luar vault atau vault tertaut.

## 📊 Hasil Pengukuran

### Ukuran keluaran tool

Diukur pada salinan vault utama (85 catatan, 680 chunk). Perkiraan token = karakter ÷ 4.

| Keluaran | Karakter | Perkiraan token |
| :--- | ---: | ---: |
| Definisi 12 tool (beban tetap per sesi) | 5.870 | ±1.470 |
| `search_brain`, mode indeks, 5 hasil | 1.670 | ±420 |
| `search_brain`, mode cuplikan, 5 hasil | 2.657 | ±660 |
| `build_task_context` | 1.964 | ±490 |
| `get_project_context` | 2.669 | ±670 |

Pembacaan:
- Mode indeks 37% lebih kecil dari mode cuplikan. Selisihnya tidak sebesar harapan karena path catatan sesi panjang.
- Beban tetap ±1.470 token per sesi berlaku walau tidak ada tool yang dipanggil. Menambah tool berarti menambah beban ini.

### Pemakaian token nyata (`devbrain usage --days 0`)

| Ukuran | Nilai |
| :--- | ---: |
| Sesi Claude Code di mesin ini | 11 |
| Token konteks total | 384 juta |
| Bagian yang dilayani cache | 97% |
| Panggilan ke tool `central-brain` | 0 |

Pembacaan:
- **Belum ada satu pun sesi yang memakai DevBrain**, jadi hipotesis hemat token belum bisa diuji dari data ini. Server MCP-nya memang mati sampai rilis ini.
- **97% konteks adalah pembacaan ulang dari cache**, yang ditagih jauh lebih murah daripada input baru. Artinya penghematan nyata datang dari berkurangnya jumlah giliran dan panggilan tool, bukan dari mengecilkan satu jawaban tool.

## ⚠️ Perubahan Perilaku

- `search_brain` kini mengembalikan daftar ringkas secara default. Agent yang butuh cuplikan panjang memanggil `detail="snippet"` atau `read_note`.
- Folder baru `00_System/Memories/` dibuat saat memori pertama disimpan. Jangan mengedit berkas di dalamnya secara manual: sumber resminya SQLite, dan berkas ini ditulis ulang oleh DevBrain.

- Penyatuan indeks ke SQLite (FTS5 + vektor).
- Mode jaringan `serve --no-stdio` dan autentikasi.
