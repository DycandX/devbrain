## Ringkasan

Memori DevBrain disodorkan ke semua agent yang tersambung. Begitu lebih dari satu agent menulis ke sana (Sprint 16 menyambungkan Hermes), satu entri berbahaya bisa memengaruhi semuanya. Rilis ini memasang gerbang sebelum itu terjadi: setiap tulisan diperiksa, bisa ditahan sampai disetujui, dan tercatat di ledger. Rilis ini juga menambah memori inti, yaitu fakta yang dipin dan selalu tampil di briefing. Polanya meniru Hermes ([dokumen 49](../brainstorming/49-siklus-belajar-hermes-dan-adopsinya-di-devbrain.md)).

## 🚀 Ditambahkan

### 1. Pemeriksa isi memori (`memory/guard.py`)
Tulisan ditolak bila:

| Kategori | Contoh yang ditolak |
| :--- | :--- |
| Instruksi untuk agent | "Ignore all previous instructions ...", "Abaikan semua instruksi ...", "You are now ...", "Do not tell the user ...", tag `</system>`, `[INST]` |
| Perintah atau pengiriman data | `curl ... \| sh`, `iwr ... \| iex`, kunci `ssh-ed25519 AAAA`, `authorized_keys`, kunci privat, "send the API key to ...", URL berisi `?token=` |
| Kredensial | Semua yang dikenali sanitizer (OpenAI, Anthropic, Google, GitHub, Bearer, password) |
| Karakter tersembunyi | Unicode kategori format (zero-width, pembalik arah) dan karakter tag |

- Agent menerima alasan penolakannya.
- Percobaan yang ditolak tercatat di ledger sebagai `blocked`, beserta 200 karakter pertama isinya.
- Diuji dengan 16 contoh jahat (semua ditolak) dan 8 fakta biasa yang mirip (semua diterima), misalnya "Ignore lint warnings in generated files" dan "Use `curl -s localhost:3000/health`".

### 2. Mode persetujuan
- Diaktifkan dengan `"memory": {"write_approval": true}` di `.brainrc.json`. Default-nya mati.
- Memori baru disimpan sebagai `pending`. Memori pending tidak punya catatan Markdown, tidak muncul di `recall`, dan tidak masuk briefing.
- Pin dan `supersedes` yang diminta baru berlaku saat disetujui.
- Teks yang sama tidak bisa diantrekan dua kali.

### 3. Perintah `devbrain memory`

| Perintah | Fungsi |
| :--- | :--- |
| `list [--status] [--project]` | Daftar memori per status |
| `pending` | Daftar yang menunggu persetujuan |
| `approve <id...\|all>`, `reject <id...\|all>` | Menyetujui atau menolak |
| `pin <id>`, `unpin <id>` | Memasukkan atau mengeluarkan dari memori inti |
| `edit <id> --old ... --new ...` | Mengganti satu potongan teks |
| `forget <id>` | Mempensiunkan memori |
| `ledger [id]` | Riwayat semua tindakan |

### 4. Memori inti
- Memori yang dipin selalu tampil di bagian **📌 Core Memory** di briefing: memori global ditambah memori projek itu.
- Ada anggaran karakter (`memory.core_char_limit`, default 2.000). Memori global dan setiap projek punya anggarannya sendiri.
- Pin yang melebihi anggaran ditolak dengan pesan jelas, bukan memotong memori lama diam-diam.
- Tool MCP `remember` mendapat parameter `pinned`. Deskripsinya meminta agent memakai pin hanya untuk fakta yang harus dilihat setiap sesi.
- Memori inti tidak diulang di bagian Remembered Facts.

### 5. Ledger memori
- Tabel baru `memory_ledger` di `brain.db`, hanya bisa ditambah.
- Mencatat `created`, `approved`, `rejected`, `patched` (dengan isi sebelum dan sesudah), `pinned`, `unpinned`, `superseded`, `forgotten`, dan `blocked`.

### 6. Edit memori
- `MemoryManager.patch()` mengganti satu potongan teks yang muncul tepat sekali. Hasilnya diperiksa ulang oleh pemeriksa isi.

## ⚖️ Penyimpangan dari Rencana

**S15-T05 tidak menambah tool MCP baru.** Rencananya edit memori juga tersedia sebagai tool MCP. Yang dibuat: `patch` di manager dan `devbrain memory edit` di CLI saja. Alasannya:
- Setiap tool menambah sekitar 100 token ke beban tetap setiap sesi, untuk semua agent.
- Memori DevBrain berisi satu fakta per entri (maksimal 1.000 karakter), jadi agent cukup memakai `remember(..., supersedes=<id>)` untuk mengganti fakta.
- Hermes butuh `patch` karena memorinya sedikit entri yang panjang. Kondisi DevBrain berbeda.
