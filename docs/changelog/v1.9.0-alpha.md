## Ringkasan

Pemindaian massal (`devbrain ingest projects`) dulu hanya melihat satu tingkat di bawah folder workspace. Folder yang berisi banyak projek, seperti `_fxmedia` (projek magang) dan `_TEST` (percobaan), terlewat seluruhnya. Rilis ini membuat pemindaian masuk ke folder semacam itu, mencatat asal-usul setiap projek, dan memisahkan projek percobaan dari projek sungguhan.

---

## 🚀 Ditambahkan

### 1. Pemindaian bertingkat
- Folder yang bukan projek tetapi berisi projek diperiksa isinya, sampai 3 tingkat (`MAX_SCAN_DEPTH`).
- Berlaku untuk pemindaian massal dan untuk folder wadah yang ditargetkan langsung.
- Folder `node_modules`, `vendor`, `venv`, `build`, `dist`, `target`, dan folder berawalan titik tidak dimasuki.

### 2. Grup projek
- Folder wadah menjadi **grup** bagi projek di dalamnya. Untuk wadah di dalam wadah, grup diambil dari folder terluar.
- Di kartu projek: `group: "<label>"` di frontmatter, tag `group/<nama>`, dan baris **Group** di bawah judul.
- Folder yang hanya membungkus satu projek tidak dianggap grup.
- Projek yang dipindai sendiri-sendiri (misalnya dibuat otomatis dari sesi agent) mendapat grup dari folder induknya bila induk itu grup yang dikenal.
- Folder dokumen di dalam grup (lebih dari 60% Markdown) dicatat ke `20_Knowledge/References/` dengan grup yang sama.

Pengaturan per grup di `.brainrc.json`:

```json
"workspace_roots": ["E:\\_PROJECT"],
"project_groups": {
  "_fxmedia": { "label": "Magang FXMedia" },
  "_TEST": { "label": "Sandbox", "sandbox": true }
}
```

Tanpa pengaturan, label diambil dari nama folder.

### 3. Sandbox
- Grup ditandai sandbox bila diatur `"sandbox": true`, atau bila kata pertama namanya `test`, `tests`, `testing`, `sandbox`, `playground`, `scratch`, `tmp`, atau `temp`.
- Kartu sandbox diberi `sandbox: true` dan tag `sandbox`.
- Kartu sandbox **tetap bisa dicari** lewat `search_brain`, tetapi **tidak pernah masuk briefing projek lain**.

### 4. Jenis projek yang dikenali

| Penanda | Dikenali sebagai |
| :--- | :--- |
| `pubspec.yaml` | Dart, dan Flutter bila bergantung pada `flutter` |
| `composer.json` | PHP, dan Laravel bila memakai `laravel/framework` |
| `pom.xml`, `build.gradle`, `build.gradle.kts` | Java (Maven / Gradle) |
| `*.csproj`, `*.sln` | C# / .NET |
| `CMakeLists.txt`, `Makefile` | C / C++ |

Daftar penanda kini ada di satu tempat (`harvester/markers.py`). Sebelumnya daftar itu ditulis ulang di empat berkas dengan isi yang berbeda-beda.

## 🐛 Diperbaiki

### 1. Vault dipindai sebagai projek
Folder yang berisi `.brainrc.json`, atau `.obsidian` tanpa manifest kode, kini dilewati. Projek berkode yang kebetulan menyimpan catatan di Obsidian tetap dianggap projek.

### 2. Nama kartu bertabrakan
- **Masalah:** kartu ditaruh di `10_Projects/<nama>`. Dua projek bernama sama saling menimpa.
- **Perbaikan:** projek yang datang belakangan mendapat awalan grup (`fxmedia-api`), lalu awalan folder induk, lalu nomor. Projek yang berada langsung di folder dipindai lebih dulu, sehingga yang tidak bergrup memegang nama polos.
- Nama bawaan alat pembuat projek (`laravel`, `my-app`, `vite-project`, `flutter_application_1`, dan sejenisnya) diganti dengan nama folder.

### 3. Tautan sesi hilang saat pindai ulang
Memindai ulang sebuah projek menulis ulang kartunya dan membuang tautan sesi di bagian "Riwayat Sesi AI Terkini". Tautan itu kini dibawa ke kartu baru.

### 4. Pratinjau pemindaian massal kosong
`--dry-run` pada pemindaian massal dulu tidak melaporkan apa pun. Sekarang melaporkan semua yang akan dibuat.

## ⚠️ Keterbatasan

- **`DOCS` dan `_Laporan Magang FXMedia` belum tercatat.** Isinya bukan mayoritas Markdown, jadi tidak lolos aturan folder dokumen. Menautkannya sebagai vault (`devbrain vault link`) adalah jalan keluar sementara.
- **Folder berisi `skills/` dianggap skill, bukan projek.** Satu projek portofolio terklasifikasi begitu. Ini aturan lama yang belum diubah.
- **Kartu lama tidak dipindahkan.** Projek yang kartunya sudah ada tetap memakai nama kartunya, dan baru mendapat `group` setelah dipindai ulang.
- **Berkas lepas tanpa manifest** (`.java`, `.c`, `.php` tanpa `pom.xml`, `Makefile`, atau `composer.json`) tidak dikenali sebagai projek.
